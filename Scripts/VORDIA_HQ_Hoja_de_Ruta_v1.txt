OBJETIVO
Construir el sistema interno de administración y dirección de VORDIA.
VORDIA HQ deberá centralizar la información empresarial y transformar datos operativos en información que permita:
 Administrar.
 Automatizar.
 Supervisar.
 Proyectar.
 Detectar problemas.
 Tomar decisiones.
VORDIA HQ será la fuente única de verdad empresarial de VORDIA.
LECTURA DEL DOCUMENTO
P0 - Crítico P1 - Importante P2 - Evolución
Base mínima para operar Segunda etapa de escala Capacidades avanzadas
1. PRINCIPIOS DEL DESARROLLO
1.1 Automation First
Todo proceso repetitivo susceptible de automatización debe diseñarse para funcionar sin intervención humana.
1.2 Exception Management
La dirección no debe revisar todo.
 Está atrasado.
 Está vencido.
 Se desvió.
 Requiere aprobación.
 Requiere decisión.
 Representa un riesgo.
1.3 Single Source of Truth
No duplicar información innecesariamente.
Cliente, producto, contrato, pago, tarea y proyecto deben relacionarse entre sí.
1.4 Trazabilidad
Los movimientos importantes deberán registrar:
 Usuario.
 Acción.
 Fecha.
 Hora.
 Valor anterior.
 Valor nuevo.
1.5 Modularidad
Construir módulos independientes pero relacionados.
1.6 Escalabilidad
No programar reglas específicas únicamente para los primeros clientes.

29. MOTOR DE AUTOMATIZACIONES - ARQUITECTURA
TRIGGER → CONDITIONS → ACTION
Ejemplo
 TRIGGER: Factura vencida.
 CONDITION: Saldo > 0.
 ACTION: Cambiar estado + enviar aviso + generar tarea.
No programar cada futura automatización rígidamente si puede implementarse posteriormente mediante reglas configurables.

DECISIONES

 Estrategia.
 Capital.
 Ventas importantes.
 Producto.
 Alianzas.
 Expansión.
 Decisiones.

propietarios no estén interviniendo constantemente.
